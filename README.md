# Cashback Merge

Мини-игра в духе 2048 на поле 4 на 4. Плитки одного уровня объединяются в следующий уровень. Уровни кэшбэка 1%, 2%, 4%, 8%, 16% и 32%. Число ходов ограничено.

Вторая часть проекта это симуляция кампании. Она покажет, какая доля игроков получает максимальную награду. Симуляция появится в MR3.

Задание описано в [TASK.md](TASK.md), работа с шаблоном в [HELP.md](HELP.md).

## Запуск

Нужен JDK 25 или новее. Команды даны для PowerShell. На Linux и macOS вместо `.\gradlew.bat` пишите `./gradlew`.

Чтобы русские буквы в консоли Windows выводились правильно, сначала включите UTF-8.

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

### Игра

```powershell
.\gradlew.bat -q run --args="play --seed 42"
```

Ход вводится буквой и клавишей Enter. Буквы w, s, a, d двигают плитки вверх, вниз, влево и вправо. Буква q завершает игру. Нужна английская раскладка.

Без `--seed` программа выберет seed сама и напечатает его. С тем же seed партию можно повторить.

### Начальное поле

```powershell
.\gradlew.bat -q run --args="init --seed 42"
```

```text
Seed: 42
   .   .   .   .
   .   .   .   .
   .   .   .  2%
   .   .   .  2%
Счёт: 0
Осталось ходов: 100
```

Тот же seed даёт то же поле.

Обе команды по умолчанию берут конфиг `config/campaign.example.json`. Другой конфиг передаётся через `--config`.

### Тесты

Тесты и линтеры, как в CI.

```powershell
.\gradlew.bat check
```

## Конфиг кампании

Пример лежит в `config/campaign.example.json`. Конфиг отклоняется в таких случаях.

- `boardSize` не равен 4.
- `movesLimit` не больше нуля.
- Список `spawnRules` пуст.
- Уровень кэшбэка не из списка 1, 2, 4, 8, 16, 32.
- Вероятность не больше нуля.
- Уровень повторяется в двух правилах.
- Сумма вероятностей не равна ровно 1.

Причина ошибки печатается одной строкой, код завершения 1. Поля наград пока не читаются, они нужны для MR3.

## Правила хода

- Плитки сдвигаются до края в направлении хода.
- Две соседние одинаковые плитки объединяются в следующий уровень. Две плитки 32% не объединяются.
- Плитка объединяется не больше одного раза за ход. Строка `[1, 1, 2, .]` влево даёт `[2, 2, ., .]`.
- Пара объединяется у того края, куда идёт сдвиг. Строка `[1, 1, 1, .]` вправо даёт `[., ., 1, 2]`.
- Счёт растёт на значение новой плитки. Слияние 1% и 1% даёт +2.
- Ход без изменений на поле не тратит лимит и не создаёт плитку.
- После хода с изменениями появляется ровно одна плитка.
- На старте на поле две плитки.
- Партия заканчивается, когда лимит ходов исчерпан. Плитка 32% её не завершает.
- Если ни один ход не меняет поле, партия заканчивается раньше. Иначе она шла бы бесконечно.

## Решения

- Уровень кэшбэка это enum `Cashback`. Лишний уровень создать нельзя.
- Поле хранит плитки в `Map<Position, Cashback>`. Ключи Map уникальны, поэтому в клетке не бывает двух плиток.
- Поле и состояние партии неизменяемые. Каждый ход создаёт новый объект.
- Конфиг проверяет себя в конструкторе. Невалидный конфиг нельзя создать ни из файла, ни в коде.
- Вероятности хранятся в `BigDecimal`, без `double`. Новая плитка выбирается по целым весам. Вероятности 0.85 и 0.15 дают веса 85 и 15.
- Вся случайность идёт через один `Random(seed)` в `TileSpawner`.
- `Slider` сдвигает и сливает плитки без случайности. `TileSpawner` ставит новую плитку. `MoveEngine` собирает ход целиком.
- Одна функция слияния работает для всех четырёх направлений.

## Структура

- В `academy.cashbackmerge` лежат `Main`, команды `InitCommand` и `PlayCommand` и вывод `BoardRenderer`.
- В `academy.cashbackmerge.config` лежат конфиг кампании и его загрузка.
- В `academy.cashbackmerge.game` лежат модель и правила игры. Этот пакет не зависит от конфига.
