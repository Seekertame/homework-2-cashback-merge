# Cashback Merge

Мини-игра в духе 2048 на поле 4 на 4. На поле появляются плитки с кэшбэком.
Две плитки одного уровня объединяются в следующий уровень: 1% + 1% = 2%, потом 4%, 8%, 16% и 32%.
Число ходов ограничено.

Вторая часть проекта это симуляция кампании. Она покажет, какая доля игроков получает максимальную награду.

Задание лежит в [TASK.md](TASK.md), работа с шаблоном описана в [HELP.md](HELP.md).

## Что готово

MR1. Модель, конфиг и начальное состояние:

- поле 4 на 4, клетки и плитки с уровнями кэшбэка;
- состояние партии: поле, счёт и сколько ходов осталось;
- загрузка конфига кампании из JSON с проверкой;
- начальное поле, которое повторяется при том же seed;
- текстовый вывод поля.

MR2. Движок ходов:

- ходы вверх, вниз, влево и вправо;
- сдвиг и слияние по правилам 2048;
- счёт, лимит ходов и новая плитка после каждого хода, который изменил поле;
- консольная игра.

## Запуск

Нужен JDK 25 или новее. Команды ниже для PowerShell. На Linux и macOS вместо `.\gradlew.bat` пишите `./gradlew`.

Чтобы русские буквы в консоли Windows выводились правильно, сначала выполните:

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

Создать начальное поле по seed:

```powershell
.\gradlew.bat -q run --args="init --seed 42"
```

Конфиг по умолчанию `config/campaign.example.json`. Другой конфиг передаётся через `--config`:

```powershell
.\gradlew.bat -q run --args="init --config config/campaign.example.json --seed 42"
```

Пример вывода:

```text
Seed: 42
   .   .   .   .
   .   .   .   .
   .   .   .  2%
   .   .   .  2%
Счёт: 0
Осталось ходов: 100
```

Тот же seed всегда даёт то же поле. Другой seed даёт другое поле.

Сыграть в консоли:

```powershell
.\gradlew.bat -q run --args="play --seed 42"
```

Ход вводится буквой и клавишей Enter: w вверх, s вниз, a влево, d вправо, q выход. Нужна английская раскладка.
Без `--seed` программа выберет seed сама и напечатает его. По нему партию можно повторить.

Тесты и линтеры, как в CI:

```powershell
.\gradlew.bat check
```

## Конфиг кампании

Пример лежит в `config/campaign.example.json`.

```json
{
  "boardSize": 4,
  "movesLimit": 100,
  "spawnRules": [
    { "cashback": "1", "probability": "0.85" },
    { "cashback": "2", "probability": "0.15" }
  ]
}
```

Конфиг отклоняется, если:

- `boardSize` не равен 4;
- `movesLimit` не больше нуля;
- список `spawnRules` пуст;
- уровень кэшбэка не из списка 1, 2, 4, 8, 16, 32;
- вероятность не больше нуля;
- уровень повторяется в двух правилах;
- сумма вероятностей не равна ровно 1.

Ошибка печатается одной строкой с причиной. Программа завершается с кодом 1.

Поля для наград (`rewardTable`, `maxRewardCashback`, `maxRewardAllowedRate`) пока не читаются. Они понадобятся в MR3.

## Правила хода

- Плитки сдвигаются до края в направлении хода.
- Две соседние одинаковые плитки объединяются в следующий уровень.
- Плитка объединяется не больше одного раза за ход. Строка `[1, 1, 2, .]` влево даёт `[2, 2, ., .]`, а не `[4, ., ., .]`.
- Пара объединяется у того края, куда идёт сдвиг. Строка `[1, 1, 1, .]` вправо даёт `[., ., 1, 2]`.
- Две плитки 32% не объединяются. 32% это максимальный уровень.
- Счёт растёт на значение каждой новой плитки от слияния. Например, 1% + 1% даёт +2 к счёту.
- Ход, после которого поле не изменилось, не тратит лимит и не создаёт плитку.
- После хода, который изменил поле, появляется ровно одна плитка.
- Плитка 32% не завершает партию.
- Партия заканчивается, когда лимит ходов исчерпан. Она заканчивается и раньше, если ни один ход не меняет поле. Иначе такая партия никогда бы не закончилась.

## Решения

- Уровень кэшбэка это enum `Cashback`. Уровней ровно шесть, лишний создать нельзя.
- Поле хранит плитки в `Map<Position, Cashback>`. Ключи Map уникальны, поэтому в клетке не бывает двух плиток.
- Поле и состояние партии неизменяемые. Любое изменение создаёт новый объект.
- Конфиг проверяет себя в конструкторе. Невалидный конфиг нельзя создать ни из файла, ни в коде.
- Вероятности хранятся в `BigDecimal`. Сумма сравнивается с единицей точно, без `double`.
- Уровень новой плитки выбирается по целым весам. Вероятности 0.85 и 0.15 становятся весами 85 и 15 из 100.
- Вся случайность идёт через один `Random(seed)` в `TileSpawner`.
- На старте на поле две плитки, как в 2048.
- Ход разделён на три части. `Slider` сдвигает и сливает плитки без случайности. `TileSpawner` ставит новую плитку. `MoveEngine` собирает ход целиком.
- Все четыре направления обрабатывает одна функция слияния. Для каждого направления клетки линии перебираются от края, к которому идёт сдвиг.
- Ход без изменений определяется сравнением поля до и после сдвига через `equals`.

## Структура

- `academy.cashbackmerge`: точка входа `Main`, команды `InitCommand` и `PlayCommand`, текстовый вывод `BoardRenderer`.
