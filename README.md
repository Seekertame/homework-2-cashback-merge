# Cashback Merge

Мини-игра в духе 2048 на поле 4 на 4. Плитки одного уровня объединяются в следующий уровень. Уровни кэшбэка 1%, 2%, 4%, 8%, 16% и 32%. Число ходов ограничено.

Вторая часть проекта это симуляция кампании. Она показывает, какая доля игроков получает максимальную награду, и укладывается ли эта доля в лимит.

Задание описано в [TASK.md](TASK.md), работа с шаблоном в [HELP.md](HELP.md).

## Запуск

Нужен JDK 25 или новее. Команды даны для PowerShell. На Linux и macOS вместо `.\gradlew.bat` пишите `./gradlew`.

Чтобы кириллица в консоли Windows выводилась правильно, включите UTF-8.

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

Все команды по умолчанию берут конфиг `config/campaign.example.json`. Другой конфиг передаётся через `--config`.

### Игра

```powershell
.\gradlew.bat -q run --args="play --seed 42"
```

Ход вводится буквой и клавишей Enter. Буквы w, s, a, d двигают плитки вверх, вниз, влево и вправо. Буква q завершает игру. Нужна английская раскладка.

Без `--seed` программа выберет seed сама и напечатает его. Во время игры видна текущая награда.

### Симуляция

Короткий запуск. Отчёт печатается в консоль.

```powershell
.\gradlew.bat -q run --args="simulate --players 1000 --seed 42"
```

Запуск как в задании. Отчёт записывается в файл `report.md` в папке проекта.

```powershell
.\gradlew.bat -q run --args="simulate --config config/campaign.example.json --players 10000 --strategy random --seed 42 --output report.md"
```

В консоли появятся путь к файлу и статус OK или FAILED.

Все опции необязательные. По умолчанию 10000 игроков, стратегия random и случайный seed, который пишется в отчёт.

Пример отчёта лежит в [docs/report-example.md](docs/report-example.md). С конфигом из примера максимальную награду получают 92% игроков при лимите 20%, поэтому статус FAILED. Если поставить в конфиге `movesLimit` 43, доля падает до 18%, и статус становится OK.

## Бонусы

### Стратегия greedy

Greedy пробует все ходы и берёт тот, что даёт больше очков. Ходы, которые не меняют поле, она пропускает. При равных очках берётся первый по порядку.

```powershell
.\gradlew.bat -q run --args="simulate --players 10000 --strategy greedy --seed 42"
```

Сравнение с random на конфиге из примера, 10000 игроков, seed 42.

| Стратегия | Средний score | Доля максимальной награды |
|---|---|---|
| random | 373.1 | 92.1% |
| greedy | 447.8 | 99.8% |

Greedy играет лучше. Живые игроки тоже думают над ходами, поэтому random занижает расходы акции.

### Генеративные тесты

`GenerativeTest` строит сотни случайных полей и проверяет три правила. Сумма плиток после сдвига не меняется. Плитка не сливается дважды за ход. Тот же seed даёт ту же партию.

```powershell
.\gradlew.bat test --tests "*GenerativeTest"
```

### Повтор партии

Сохранить партию. В файл пишутся seed и ходы.

```powershell
.\gradlew.bat -q run --args="play --seed 42 --save game.txt"
```

Повторить её.

```powershell
.\gradlew.bat -q run --args="play --replay game.txt"
```

Повтор проходит через те же поля и даёт тот же итог. Если партия шла с другим конфигом, его нужно передать и при повторе.

## Конфиг кампании

Конфиг отклоняется в таких случаях.

- `boardSize` не равен 4.
- `movesLimit` не больше нуля.
- Список `spawnRules` пуст.
- Уровень кэшбэка не из списка 1, 2, 4, 8, 16, 32.
- Вероятность не больше нуля.
- Уровень повторяется в правилах появления или в таблице наград.
- Сумма вероятностей не равна ровно 1.
- Таблица наград пуста или в ней есть отрицательная награда.
- Уровня `maxRewardCashback` нет в таблице наград.
- Доля `maxRewardAllowedRate` меньше 0 или больше 1.

Причина ошибки печатается одной строкой, код завершения 1.

## Правила хода

- Плитки сдвигаются до края в направлении хода.
- Две соседние одинаковые плитки объединяются в следующий уровень. Две плитки 32% не объединяются.
- Плитка объединяется не больше одного раза за ход. Строка `[1, 1, 2, .]` влево даёт `[2, 2, ., .]`.
- Пара объединяется у того края, куда идёт сдвиг. Строка `[1, 1, 1, .]` вправо даёт `[., ., 1, 2]`.
- Счёт растёт на значение новой плитки. Слияние 1% и 1% даёт +2.
- Ход без изменений на поле не тратит лимит и не создаёт плитку.
- После хода с изменениями появляется ровно одна плитка.
- На старте на поле две плитки.
- Партия заканчивается, когда лимит ходов исчерпан. Плитка 32% её не завершает.
- Если ни один ход не меняет поле, партия заканчивается раньше. Иначе она шла бы бесконечно.

## Награды и симуляция

- Награда считается по максимальной плитке на поле.
- Таблица наград задаёт пороги. Игрок получает награду за самый высокий уровень таблицы, которого достиг. Если в таблице нет 8%, плитка 8% получит награду за 4%. Ниже всех уровней награда 0.
- Максимальную награду получает игрок, чья плитка не ниже `maxRewardCashback`.
- Стратегия random выбирает направление наугад. Если ход ничего не изменил, она выбирает снова.
- Статус OK, если доля игроков с максимальной наградой не больше `maxRewardAllowedRate`. Иначе FAILED. Доля сравнивается без округления.
- Это оценка для конкретного конфига, seed, числа игроков и стратегии, а не гарантия.

## Решения

- Уровень кэшбэка это enum `Cashback`. Лишний уровень создать нельзя.
- Поле хранит плитки в `Map<Position, Cashback>`. Ключи Map уникальны, поэтому в клетке не бывает двух плиток.
- Поле и состояние партии неизменяемые. Каждый ход создаёт новый объект.
- Конфиг проверяет себя в конструкторе. Невалидный конфиг нельзя создать ни из файла, ни в коде.
- Вероятности хранятся в `BigDecimal`, без `double`. Новая плитка выбирается по целым весам. Вероятности 0.85 и 0.15 дают веса 85 и 15.
- `Slider` сдвигает и сливает плитки без случайности. `TileSpawner` ставит новую плитку. `MoveEngine` собирает ход целиком.
- Одна функция слияния работает для всех четырёх направлений.
- Вся случайность идёт через один `Random(seed)`. Поэтому одинаковые конфиг и seed дают одинаковые партии и отчёт.

## Структура

- В `academy.cashbackmerge` лежат `Main`, команды `InitCommand`, `PlayCommand` и `SimulateCommand` и вывод `BoardRenderer`.
- В `academy.cashbackmerge.config` лежат конфиг кампании с таблицей наград и его загрузка.
- В `academy.cashbackmerge.game` лежат модель и правила игры. Этот пакет не зависит от конфига.
- В `academy.cashbackmerge.simulation` лежат стратегии random и greedy, симуляция и отчёт.
